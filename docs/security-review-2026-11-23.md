# Pre-deployment security review, 2026-11-23

> **Status:** every finding below has been fixed or has a recorded decision; see [security-hardening-2026-11-23.md](security-hardening-2026-11-23.md) for the merged findings, the plan, the fixes and the evidence.

Reviewed commit `f14b7b9` on desktop-mac. This is a source review, not a penetration test or an independent audit of Zig, Ghostty, wterm, xterm.js, Rex, or Tailscale. No deployment, live Rex session, or listener configuration was changed. Phase 3's week of daily use has not been recorded as complete. Do not treat this review as authorization to deploy.

## Findings

1. **High: macOS loopback accepts a forged Tailscale identity.** With `--listen-tcp` and `--owner`, the CLI does not require a token (`src/bridge/cli.zig:118-121`); TCP has no peer check (`src/bridge/server.zig:97-100`); and `access.decide` trusts the supplied login and forwarded host (`src/bridge/access.zig:96-99,116-119`). Any local account or process able to connect can forge these headers, open a WebSocket with a matching Origin, read terminals and run commands as the bridge user. The own-address rule does not help when X-Forwarded-For is omitted. This is a known design concession, but the plan excludes only processes running as the owner's user, not all local users. Resolve with an authenticated proxy-to-backend transport or another enforceable boundary; a static token exposed to the same local adversary is not automatically sufficient. Verify the chosen boundary on macOS before deployment.

2. **High: security checks can ignore headers after the first 48.** `src/bridge/server.zig:197-204` silently truncates the list passed to access control. If an otherwise valid request places `Tailscale-Funnel-Request` or an own-address `X-Forwarded-For` after that point, the respective check does not see it. Identity and origin still need to pass. Actual exploitability through Serve depends on its header ordering and rewriting; this was not tested. Reject overflow, inspect every header, and handle duplicates deliberately. Add wire tests including headers inserted by Serve.

3. **Medium: no deadline before authentication allows connection exhaustion.** `src/bridge/server.zig:154-159,183-192` reserves one of 64 slots and waits for the complete HTTP head before checking the peer or identity. A client that can reach the listener and hold connections open can occupy all slots without authenticating. Whether remote clients can sustain this through a particular Serve version depends on its own timeouts and buffering. Enforce a head-read deadline, check unix peer credentials immediately after accept, and test saturation and recovery through Serve and directly on loopback.

4. **Medium: diagnostic endpoint logs credentials and arbitrary query content.** `src/bridge/server.zig:255-256` logs the entire query string after authentication. A request such as `/api/lab/result?token=...` writes the token into logs; clients can also put sensitive content there. The normal request log strips queries. Remove the lab endpoint from release builds or log only bounded, validated diagnostic fields; never log token-bearing queries. `--debug-input` also intentionally logs typed input and must be disabled in deployment.

5. **Medium: WebSocket masking is not enforced.** `src/rex/ws.zig:317-346` accepts both masked and unmasked frames regardless of client/server role. Browser-to-server frames must be masked; enforce the role and test over the actual upgraded connection. This is a protocol and defense-in-depth defect; no concrete cross-origin or proxy-cache exploit was demonstrated here.

6. **Medium: wterm query suppression fails open.** `src/bridge/web/wterm-shim.js:18-22` only suppresses terminal query replies if a private `bridge.getResponse` method exists. A dependency or API change can silently reinstate replies as terminal input, contrary to the plan's terminal safety constraint. Fail initialization or fall back if the hook is absent, and add an end-to-end test that injects query sequences and proves no input reaches Rex for both terminal implementations.

7. **Low: own-address comparison is textual and missing X-Forwarded-For is accepted.** `src/bridge/access.zig:101-108` compares exact strings and treats a missing header as safe. Equivalent IPv6 spellings or a missing/misconfigured proxy header can bypass this defense. Normalize addresses and fail closed when the rule is enabled; validate the actual Serve header format and duplicate handling.

## Other boundaries and decisions

- Unix listener creation uses a 0600 socket in a directory checked for group/other access, and verifies peer UID on requests. The check is too late for connection exhaustion as noted above. `Server.start` unlinks the configured path without verifying that it is a stale socket (`server.zig:89-95`); packaging must use a dedicated path, and the implementation should refuse existing non-socket files and active listeners.
- Observe-only checks cover input, management and terminal actions in the hub, and the locked setting cannot be toggled by the browser. It still permits terminal content, metadata and clipboard reads. It is not a confidentiality boundary.
- The CSP permits WebAssembly compilation through `'wasm-unsafe-eval'`, which wterm needs; this is narrower than `'unsafe-eval'` but expands the capability of any script already executing in the page. Scripts and wasm are served locally. The wterm bundle and wasm are executable dependencies; the available provenance is recorded in `phase3-result.md`. Their source, build reproducibility, vulnerabilities and terminal escape/link handling were not independently audited. Review and pin the full supply chain before release.
- File transfer remains unimplemented. Adding it would grant the page file access with the bridge user's authority and needs a separate design and review, including path and symlink handling, authorization, size limits and download disclosure. This review does not approve it.
- Browser message sizes and rate, viewer queues, input backlog, snapshot size and parser fuzz targets have limits. Limits are not a proof against memory exhaustion or CPU amplification. Snapshot decoding retries while accumulating data; adversarial output, very large redraws, slow readers, fragmentation and connection churn need targeted stress testing.
- Random test tokens appear in the startup URL and browser history; the page also forwards `location.search` to its WebSocket. They are intended for local tests and should be treated as secrets. Use a safe bootstrap that removes the token from the URL, and never use `--debug-input` for deployment.
- Tailscale documents stripping incoming identity headers, but an exposed TCP backend remains forgeable by local clients. See https://tailscale.com/docs/features/tailscale-serve. Validate forwarding, origin, Funnel refusal and own-address behavior with the installed versions and deployment configuration rather than assuming proxy behavior.

## Checks and limits

- `git status --short --branch`: clean before review. Default `.git/hooks` contains only `.sample` files; no configured `core.hooksPath` or repository hook manager was found.
- `node --test tests/web/keys.test.mjs`: 12 passed. These are frontend logic tests, not security tests.
- `zig build test -Doptimize=ReleaseSafe` and `zig build web-test`: both stopped before running with `error: checking cache failed: manifest_create PermissionDenied`. Retrying the Zig suite with cache directories under `/private/tmp` had the same result. Prior test results are in the phase records; they do not substitute for this run.
- No live attack reproductions, fuzz campaign, dependency audit, cross-browser security tests, macOS multi-user test, or tests through Tailscale Serve were performed in this review. Rex/API versions recorded by the earlier runs were desktop-mac preview.21/revision 18 and linux-box preview.22/revision 19; neither was re-queried here.
